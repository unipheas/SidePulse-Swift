# Testing SidePulse

Use a Mac with Xcode selected as the active developer directory. UI tests also require XcodeGen (`brew install xcodegen`) and an unlocked graphical login session.

```sh
swift test
RUN_UI_TESTS=1 RUN_CLASSIFIER_TESTS=1 MIN_COVERAGE=99.9 Scripts/test-coverage.sh
Scripts/package.sh --universal
```

Stop an installed native eject guard with `sidepulsectl sdejectguard stop` before the disposable-disk tests, then restore it with `sidepulsectl sdejectguard start` afterward. A second guard can correctly protect the test fixture and interfere with its cleanup.

The coverage command runs the Swift tests, real CLI integration tests, a disposable FAT12 disk image, and optionally XCTest UI automation. Test configuration, hooks, relay tokens, and event logs live in temporary directories. CLI bridge tests use a loopback HTTP server. UI tests disable hardware output and privileged power changes. The disk test attaches its own tiny image and detaches it afterward; it does not select an existing disk.

`Tests/PulseCoreTests/Fixtures` contains expected outcomes generated by the original Python implementation. `Scripts/reference-events.py` regenerates those developer fixtures when its Python dependencies are available. The installed application and CLI do not require Python. Python is used only by development integration harnesses.

## Current evidence

The 0.2.1 validation covers **220 native XCTest methods (one opt-in hardware check skipped in the ordinary suite), 2 classifier template tests, and 21 UI workflows**, plus CLI, MLX process, FAT12 image, and eject/remount integration checks. Combined LLVM line coverage is **100% (10,339 of 10,339 instrumented lines across 71 production files)**; function coverage is **1,533/1,533**, and the C adapter covers **58/58 instrumented branches**. See [the source fingerprint and measurement evidence](Tests/Evidence/coverage-0.2.1.json).

The total combines the refreshed native suite, explicit installed-app acceptance, and the successful UI run. UI sources did not change after that run; the only subsequent production change was the launch retry helper, which the refreshed native suite exercises. The UI profile contains no counters for that helper. LLVM region coverage is 97.81% and generic instantiation coverage is 99.62%; 100% line coverage is not a claim that every compiler region or possible behavior was exercised.

The full report includes every production Swift and C file in the main package and the separate native classifier. Set `RUN_CLASSIFIER_TESTS=1` on Apple silicon to include the helper; a run without that flag explicitly reports that it is omitted. Compiler-generated SwiftUI regions can make counts differ between compiler versions.

Reports are written to:

- `.build/coverage-report/html/index.html`: combined line coverage.
- `.build/coverage-report/coverage.json`: machine-readable production coverage.
- `.build/ui-tests/results.xcresult`: UI test actions, failures, and screenshots.
- `.build/ui-tests/coverage.json`: Xcode's separate UI coverage report.

The UI workflows check invalid and valid Done durations, persistence after relaunch, profile creation and deletion, all eight compact animation previews and individual editors, history metric selection, isolated hook installation/removal, navigation, and visible working → done → idle transitions. Unit tests also cover settings migration, protocol negotiation and errors, verified firmware transfer to a simulated volume, malformed hooks, pending permissions, transcript recovery, sleep ownership and crash recovery, and launch-agent rollback.

GitHub Actions runs the native suite and universal packaging on Apple Silicon and Intel. Separate jobs run AddressSanitizer, ThreadSanitizer, and the UI workflows. The coverage floor is a regression guard, not a claim that all branches are covered.

## Physical acceptance

A connected Pro running firmware 1.1.0 passed a mounted-volume working → done → idle cycle. With Done configured for 15 seconds, the custom All Clear program returned to Night Patrol after 14.9 seconds between file observations in the final installed-app check. This test exposed and fixed a DNS lookup that had blocked the native monitoring loop.

The native eject guard now passes a real Disk Arbitration test against a disposable HFS+ image: baseline eject succeeds, a simulated Pro is protected and remounted, and an ordinary image can eject. This exposed and fixed a lookup performed after macOS had already unmounted the volume. The installed guard has been replaced by the native implementation.

The physical Pro READ2ME check passed: the real device acknowledged the transaction, CRC and byte count, then its original light program was restored. At that checkpoint, physical Dot, mobile pairing, firmware flashing, and closed-lid power changes remained unverified; the later Nova Dot checks are recorded below. Protocol simulations and dry runs do not replace those checks. Dot and mobile testing are deferred until the devices are available. No real firmware or privileged sleep settings were changed during the automated suite.

The expanded suite includes injected USB discovery/transfer failures, raw-device sizing errors, Dot transport release/reconciliation, bounded firmware streaming, transcript cache updates, relay stop/restart and retry behavior, synthetic audio RMS/smoothing/cancellation, scoreboard feed errors, notch geometry/rendering, and local Apple Intelligence generation when the model is available. Hardware fault simulations do not imply that a physical Dot was tested.

The audio adapter also passed a brief in-memory microphone capture on the development Mac, which already had microphone permission. That test skips when permission is not already authorized and does not save or transmit audio.

The optional MLX classifier uses native Swift/Metal with the original Qwen model and few-shot prompt. Token-for-token comparison against Python exposed a Jinja whitespace mismatch; the corrected renderer and four captured Python results now match. This establishes port compatibility, not general model accuracy. Tests use only synthetic messages. The classifier's transitive Collections dependency is pinned for Xcode 16.4 compatibility, and Xcode builds use Xcode's C/C++ compiler to keep coverage runtimes consistent.

Additional regression tests cover in-place library edits, legacy timing and sleep preferences, first-run setup choices and failure recovery, transport deduplication across reconnects, Disk Arbitration daemon restarts, microphone tap cleanup after failed starts, and terminal watch rendering. The full 0.2.1 native run executed 219 methods with zero failures and one opt-in Pro test skipped; a focused 24-method run also passed after adding the service retry check, bringing the unique method count to 220. The physical Pro check passed during 0.2.0 acceptance. The native menu-bar, URL-routing, and update-error workflows pass.

ViewInspector is a pinned, test-only dependency for exercising SwiftUI action closures with injected system operations. It is not linked into the app. Native window rendering and the separate XCTest UI suite still validate layout and real interaction. Network adapter tests intercept fixture responses in URLProtocol; they do not download or flash firmware.

`ProAcceptanceTests` is an explicit live-device check. Set `SIDEPULSE_PRO_ACCEPTANCE=1` and run only that suite after stopping other SidePulse writers. It exercises the Pro READ2ME transport, checks the firmware acknowledgement and restores the original light program. Ordinary automated runs skip this test.

## Installed-app coverage

The isolated suite deliberately avoids replacing the user's installed app or launch agents. The final three lifecycle lines are measured during explicit installation acceptance: stopping the installed GUI, configuring its service, and completing native setup. Use an instrumented app built from the same source revision, set `LLVM_PROFILE_FILE` to a private acceptance directory, and preserve settings and launch configurations before this check. Never run this on an unattended CI worker as an implicit installation step.

Keep a copy of the complete suite's `all.profdata` before subsequent tests. The acceptance directory's `sources.json` records SHA-256 hashes of every production Swift and C source, including the classifier. `Scripts/merge-install-coverage.py BASE.profdata ACCEPTANCE_DIRECTORY` refuses changed source fingerprints, merges the real profiles, checks that every production source appears, and requires exactly 100% line coverage. It writes the HTML/JSON reports and `acceptance-evidence.json` without modifying the installation.

## Opt-in physical Dot acceptance

After stopping all other SidePulse writers, set `SIDEPULSE_DOT_ACCEPTANCE=1` and
`SIDEPULSE_DOT_MOUNT=/Volumes/PulseDot`, then run `swift test --filter DotAcceptanceTests`.
The test requires a detected two-LED Dot with firmware at least 1.1.0. It snapshots
and restores the original light program, checks a mounted-volume write, and injects
an EROFS open failure to exercise the actual IOKit/SPC2 fallback and its acknowledgement.
Only the read-only trigger is simulated. This does not prove visible LED colors,
physical cable recovery, operation without a mounted volume, or firmware flashing.
Ordinary runs skip this test.

## Nova Dot acceptance and discovery responsiveness

On November 7, 2026, a two-LED Dot running firmware 1.1.14 passed mounted-volume
writes/readback and actual SPC2 acknowledgements. The fallback test injected the
read-only open failure; it did not change volume permissions. Three built-in
profiles, eight agent modes, brightness boundaries, and sixteen preserved custom
programs were exercised. A user separately confirmed red, green, blue, opposite
left/right colors, and off on the physical LEDs. Rapid protocol loops are not
visual confirmation of every animation.

A real Codex session, after approving its replacement native status hooks through
Codex's normal trust UI, produced SessionStart, UserPromptSubmit, PreToolUse,
PostToolUse, and Stop events. Mounted-program observations measured Done to Idle
at 14.962 seconds, and Stop timestamp to Idle at 15.243 seconds with the default
one-second service polling interval. Two overlapping real Codex sessions also retained Working after the shorter
session stopped, then returned Done to Idle after the longer session stopped
(14.899 seconds between output observations; 15.714 seconds from Stop to Idle).
Additional isolated overlap/needs-input checks used synthetic hook events on the
real device; their Done holds were 14.982 and 15.046 seconds. A 60-second sustained run at 0.1-second polling used 2.94% mean / 3.4%
peak CPU and 15,840–15,888 KiB RSS, with no transport errors. These are short-run
process measurements, not an indefinite leak guarantee.

Initial GUI launch blocked in synchronous removable-volume discovery. Default
discovery now runs off the main actor, with only one outstanding scan and
main-actor publication. Regression tests cover responsiveness, single-flight
behavior, persistence errors, and deallocation while a scan is pending. A blocked
OS read cannot itself be cancelled; it must return before the detached scan exits.
This fixes discovery blocking window creation, not all possible synchronous I/O
when the GUI itself owns hardware output. The normal installed service owns output.

The Nova UI run exposed a selector collision with Apple's hidden Recent Items >
Terminal menu item. The picker helper now chooses only a hittable matching item
from the open menu. The focused session-preferences workflow passes without
opening the unrelated system-menu entry.

The final complete native baseline passed 224 tests with five explicit skips, and
the opt-in live Dot check passed separately. The classifier's two template tests
and synthetic integration cases passed, as did CLI, FAT12 image, and eject-guard
integration. After isolating attached-volume discovery, all 21 UI workflows passed
in a single run (557.409 seconds). Earlier runs exposed removable-volume prompts
and the picker collision described above. The UI target defines
`SIDEPULSE_UI_TESTING` only for its test-host app and injects empty discovery.
SwiftPM production builds do not define that flag; default discovery is covered
by native regression and installed-app/physical acceptance, not by the UI host.

The final exact-source merged production line measurement is **10,292/10,364
(99.31%) across 71 production files**, including the full final native/UI runs,
live Dot test, and instrumented installed-app acceptance. Modified App.swift and
Dashboard.swift are 100% line-covered. This does **not** meet the requested 100%
total: 48 uncovered lines belong to microphone capture on this Mac without an
input device, and 24 are existing export/lifecycle/platform paths. The exact 100%
verifier correctly rejects this measurement. Historical MacBook evidence above
is not substituted, and no coverage threshold has been lowered.

Normal unmount/remount preserved the Dot's identity, accessibility, and `nobrowse`
mount flag. Physical cable/port/hub changes and sleep/wake were not exercised at
the user's direction. Mobile pairing, firmware flashing, and Pro-only features
were outside this Dot acceptance. The final universal release executables match
the package byte-for-byte and contain no profiling sections. All sixteen custom
programs and both saved profiles are preserved. The old Python-only runtime and
its three startup entries were moved to recoverable Trash after backup and native
physical verification; general Python, settings, and history were retained.

## Local agent integration

The isolated local-agent tests cover private minimal snapshots, concurrent runs
and writers, source namespacing, duplicate/out-of-order updates, terminal replay,
heartbeat expiry to Unknown, latched attention, explicit acknowledgement, retention,
unsafe/corrupt input, CLI parsing and exclusion from the existing remote relay.
The Python adapter tests mock its telemetry and child processes. A separate real-CLI
harness uses only temporary state and synthetic child processes, no hardware, models,
installed services or network listeners:

```sh
swift test --filter LocalAgentTests
python3 -m unittest discover -s Integrations/tests -v
python3 Tests/Integration/local-agents.py "$(swift build --show-bin-path)/sidepulsectl"
```

The published coverage evidence above describes the earlier source fingerprint.
It is not a coverage claim for these new source files. Installation and actual agent
client wiring require a separately coordinated acceptance check.

A local implementation checkpoint passed 285 native tests (7 opt-in/platform skips),
9 adapter tests, the real-CLI local-agent harness, and the existing CLI regression
harness. The two new Swift production files each reached 100% line coverage in
that native run. This is not the whole-project CI coverage gate. See the
[source fingerprints and scoped results](Tests/Evidence/local-agent-integration.json).


## Per-output animation profiles

`swift test --filter OutputProfileTests` covers independent Dot/Pro/Notch selection,
all eight states and LED counts, saved/custom/missing profiles, global fallback,
settings preservation, deletion, simultaneous hardware routing, reconnects,
unchanged-program suppression, and manual/battery/brightness/lid precedence.
The Notch policy tests cover every state with battery and power-preview combinations;
a hidden state returns no program so the existing display path hides its panel.
ViewInspector exercises the actual picker and visibility-toggle actions with the
Notch disabled and output ownership injected, without launching the installed app.
All preferences and fake device files are isolated in temporary directories, and
hardware writes in the new runtime tests are captured by an injected closure.
These checks do not claim physical-device or rendered-window acceptance.

## Hybrid Pro display

`HybridDisplayTests` checks the fixed battery bands, charging and unavailable
states, all agent-state colors, and multi-cycle output through the bundled
firmware simulator. It also checks model routing, unchanged-program suppression,
brightness, lid and manual precedence, power-change behavior, mirror-off, and
connected/disconnected picker persistence using isolated settings and injected
writes. The renderer itself reached 41/41 instrumented lines in the focused run;
that number is not a whole-project coverage measurement. No physical device
writes or installation are performed by these tests.
